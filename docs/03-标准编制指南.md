# 03 标准编制指南

**文档体系 v1.0 · 操作指南 · 读者：岗位族标准编制者、企业接入对接人、学校教务与专业负责人**

标准层是用原子词表写成的行业标准与教学标准（词表与内核见[《01 能力语义空间规范》](01-能力语义空间规范.md)）。本指南回答三个"怎么编"：岗位族标准怎么编、企业岗位模型怎么建、专业培养标准怎么映射。

---

## 1. 岗位族标准

一个岗位族的完整职业画像，对标国家职业标准的角色，由平台牵头、校企共商共建。

### 1.1 组成模板

| 组成 | 必选 | 说明 |
|------|------|------|
| 标准元信息 | 必选 | 岗位族名、版本、维护责任方 |
| 任务群 | 必选 | 典型工作任务分解 |
| 能力要求 | 必选 | 引用条目 ID + 基准等级，30–50 条为宜；**先查全局库，能引用不新建**；D1-C1 伞节点与主题组**不得作为能力要求条目**（其值为派生上卷，要求须落在可直接受证的条目上） |
| 通用能力语境化 | 必选 | 将相关通用条目实例化为本岗位语境描述（如 D4-C1 →"现场沟通与测评范围说明"）；评价表使用语境化描述，声明记录在全局通用条目上，保持跨域可比 |
| 知识要求 | 自动派生 | 由所引条目的前置知识域自动派生，编制时可增补（如法律法规类）；**增补部分 v1 仅进标准文档与 JD 导出展示，不进可行性计算**（可行性只用条目的前置知识域，《02》第 9 节） |
| 资质门槛 | 可选 | 证书等硬性条件（如等级测评师证书），匹配时作**二值过滤器**（持有对应认证字典行的过审 F 类证据即满足，不看声明等级，《02》第 9 节），独立于能力声明 |
| 级别档案 | **可选** | **固定四级**（见习 / 初级 / 中级 / 高级，不设第五职级）；每级为"条目 → 要求等级"表（**L1–L4，见习级亦最低 L1**——L0 永不参与匹配与角色等级判定，《01》第 3 节；高级条目可要求 L3 或 L4，由编制方判断，不由系统映射）+ 该级**资质门槛**（进算法，二值）与**经验门槛**（**展示字段，v1 不进算法**——学生侧无可核验工龄数据源，启用须先有数据源，《02》第 9 节）；**D1-C1 与主题组不得列入级别档案**（同能力要求禁入口径）；配置方式见 1.3 |
| 字典关联 | 可选 | 本岗位族相关的竞赛 / 认证白名单及条目映射 |
| 评价问题库 | 随级别档案 | 由级别档案派生，见 1.4 |

### 1.2 可评价性原则与语境化

**抽象的通用能力不可直接评价，只有在岗位或活动语境中实例化后才可观察。** 抽象通用条目仅作为跨领域聚合与展示的坐标。

语境化的做法：为本岗位族相关的每条通用条目写一句本岗位语境的行为描述，评价表展示语境化描述、勾选落在全局条目编码上。语境化描述随标准版本化，不新建条目。

### 1.3 级别档案与核心 / 一般标注（配置化）

级别档案是**可选组成**——并非所有岗位族都有清晰的职级分层，没有就不配，系统按配置执行：

- **配置了级别档案**：每级列出条目等级要求（**最低 L1**；某条目在见习级"接触即可"的，用**该条不列入见习级**表达，不发明第四种满足算法），每条要求可标注**核心 / 一般**（配置字段，编制方按行业共识与访谈自行判断，平台不立统一判据）。匹配时输出角色等级：R 级达成 = 核心条目全部满足 + 一般条目满足 ≥ 2/3（条数向上取整，《02》第 9 节），**各级独立判定、取满足的最高级**（不要求先低后高；某级条目表可为空，该级即永不达成；不允许跳级编号）；判定只消费条目要求与该级资质门槛，**不消费偏好过滤与经验门槛**（《02》第 9 节）；**核心 / 一般仅用于角色等级判定，与岗位模型的硬性 / 软性 / 加分标注（第 2 节）是两套口径，禁止复用**；D1-C1 与主题组不得列入级别档案（1.1）；
- **未配置级别档案**（或已配置但未做核心 / 一般标注）：匹配**不输出角色等级，只输出逐条目匹配清单**（"满足 12/15 条"+ 缺口明细）。宁可少输出一个口径，不输出一个可能错的结论。

级别档案的等级表述可直接沿用行业职级（见习 / 初级 / 中级 / 高级），与分级模板天然同构（L0–L4，见《01》第 3 节）。

### 1.4 评价问题库

- **题源**：级别档案中各级"可独立承担的工作 / 典型交付成果"，结合条目语境化描述生成；形态为行为判断句（"该生能否独立完成 X 类交付？"）；
- **用途**：① 结项总评界面的**引导参考**——每条目旁可展开对应判断句，帮评价人校准打档（不做档位推导，评价人直接打档，见《04》第 4.2 节）；② 企业面试参考题；
- 随岗位族标准同轨版本化。

### 1.5 编制流程

```mermaid
flowchart LR
  A["素材获取<br/>存量行业标准转录（优先）<br/>或 20 份以上真实 JD + 工程师访谈"] --> B["任务群与条目草案<br/>先查全局库，能引用不新建"]
  B --> C["语境化 + 级别档案（可选）<br/>+ 字典关联"]
  C --> D["试点校准一学期"]
  D --> E["定版发布（学期节奏）"]
```

- 新条目需求走词表准入审查（《01》第 2.3 节），不得为单一标准私设条目；
- **接入新岗位族不得修改内核**——18 条通用条目、分级模板、关系集均不可动，个性内容全部进标准层；
- 发布与版本迁移规则见[《05 治理与合规章程》](05-治理与合规章程.md)。

### 1.6 编制检查清单

- [ ] 能力要求全部引用现有条目 ID，新条目已走准入审查
- [ ] 条目数 30–50 条，无近义条目并存
- [ ] 相关通用条目已语境化
- [ ] 知识要求已从前置知识域派生并核对增补
- [ ] 级别档案（如配置）逐级完整，各级条目要求 ≥ L1，核心 / 一般标注已确认（未标注则明确本标准不输出角色等级）；经验门槛仅作展示，未被写成判定条件
- [ ] 资质门槛与字典关联已核对认证字典
- [ ] 评价问题库已随级别档案生成
- [ ] 未修改任何内核资产

## 2. 企业岗位模型（结构化 JD）

岗位模型 = 岗位族标准的实例化 + 企业增量 + 非能力字段。岗位模型是 HR 维护的可复用人才标准，与挂时间窗、名额的**岗位发布**（招聘实例）分离，产品形态见《04》第 4.4 节：

- **增量**：等级调整、条目增删，以及**每条能力要求强制三选一标注：硬性 / 软性 / 加分**（默认软性）——硬性只做过滤、软性进匹配度分母、加分只做并列排序键（《02》第 9 节）；D1-C1 与主题组不得作为模型条目，也不得标硬性；**资质门槛在模型确认时钉定为封闭集合**：默认继承标准级资质，企业可增补、不可删至空（标准本无资质门槛的除外）——岗位匹配硬过滤只消费该集合（《02》第 9 节）；
- **非能力字段**：地点、薪酬带、工作性质、汇报线等，与学生目标偏好双向匹配；
- 可一键生成对外发布的完整 JD 文档。

**十分钟接入流程**：

```mermaid
flowchart LR
  A["企业粘贴现有 JD"] --> B["大模型初翻为岗位模型<br/>（对齐岗位族标准 + 识别增量）"]
  B --> C["企业确认与微调<br/>约十分钟"]
  C --> D["岗位模型生效<br/>参与匹配，可一键导出 JD"]
```

大模型只做初翻，**企业确认后岗位模型即生效、参与匹配**——平台审查采用抽检 + 举报下架（对模型的举报处置经由岗位发布举报连带停用，《07》第 3.6 节），不阻塞生效（《05》第 2 节同口径）；模型的版本化（草稿 / 已生效 / 停用，编辑产生新版本、开放快照钉旧版本）见《04》第 4.4.1 节；引用模型的**岗位发布**在上线前另行走轻量合规预审（《04》第 4.4.1 节）。挂在草稿岗位族下的模型在该岗位族标准发布后的自动对齐口径见《04》第 4.4.1 节。用人反馈回流持续校准本企业岗位模型，使其沉淀为可复用、可继承的结构化资产。

## 3. 专业培养标准（学校侧）

培养方案的映射产物：**课程 → 知识点 → 知识域 / 能力目标**，学校自主维护，挂接时平台复核。

映射方法：

1. **借道存量 OBE 矩阵**：通过工程教育认证的专业已有"课程目标 → 毕业要求指标点"矩阵，且毕业要求体系与 D1–D5 高度同构，映射工作以翻译存量矩阵为主，不重做调研；
2. **课程大纲 → 知识点**：由大模型初翻、教务抽检（《02》第 8 节）；
3. **知识点 → 知识域挂接**：学校知识点到平台知识域的一次性映射，此后课程更新只维护校内侧；
4. **课程 → 能力目标**：课程声明训练哪些条目（发布时不预标等级，与活动规则一致）——**与《08》第 1.1 节课程目录的"条目勾选"是同一字段**，维护入口唯一为课程目录，本节的映射页是同一份数据的另一种视图；知识点挂接（第 2、3 点）仍为独立字段。

映射产物的用途：学生画像的课程证据挂载、推荐可行性计算（前置知识域覆盖）、教改支持报告的课程—条目贡献度分析。

## 4. 常见问题

- **"这个词该建知识点还是能力条目？"** —— 用三问口诀（《01》第 4.1 节）；同一个词可以在知识、能力、任务三个坐标各建节点（同名三投影），不争本质；
- **"标准里想要的条目库里没有"** —— 提交词表准入申请（随时收案、学期发布），不要用近义词凑合，也不要私设编码；
- **"两个标准对同一条目的等级要求不同"** —— 正常现象，等级要求属于标准层，条目本身与分级标尺是共用的；
- **"挂靠位置有争议"** —— 先按口诀挂上使用，异议提交联合评审委员会，裁决记入判例库（《01》第 4.3 节）。
