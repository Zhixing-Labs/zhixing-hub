# 06 试点实施计划

**文档体系 v1.0 · 落地路线 · 读者：项目管理、全体团队**

试点范围：两个学院、两个岗位族，跨度约一学年（筹备半学期 + 首学期试点 + 学期末校准）。总验收标准：**首批画像可生成、每个结论可展开证据链、第一轮校准完成并发布字典 v2**。

试点以高校认证学员与合作企业为主体；政务端看板与平台学员通道（《07》）随平台版本上线，**不设试点验收门槛**。

---

## 1. 五阶段路线

| 阶段 | 时间 | 内容 | 交付物 | 验收口径 |
|------|------|------|--------|---------|
| 1 定稿内核 | 筹备期 | D1–D5 与 18 条、分级模板、证据信封、门槛表、观察聚合规则与时效参数初值定稿冻结 | 《01》《02》定稿（本文档体系即交付物） | 委员会过审，v1.0 冻结 |
| 2 编制标准 | 筹备期 | 两份岗位族标准：**网络安全**（存量行业标准转录为主）、**算法工程师**（20+ JD + 工程师访谈编制） | 两份岗位族标准 v1（含语境化；级别档案按各自情况配置） | 通过《03》编制检查清单，联合评审过审 |
| 3 映射存量资产 | 筹备期—学期初 | 两学院核心课程 10–15 门（借道 OBE 矩阵）、首批实训项目 2–3 个、竞赛与认证白名单定档 | 课程映射表、项目任务分解与条目勾选、白名单字典 v1 | 教务抽检通过；字典过定档自洽约束校验 |
| 4 首学期试点 | 首学期 | 采集证据（实训评价、课程、自报导入），生成首批画像；**内部使用，不对外输出结论** | 首批学生画像 + 审计链抽查报告 | 任一结论可反向遍历到原始载荷；评价交互红线达标（日评 10 秒 / 任务评 1 分钟实测） |
| 5 第一轮校准 | 学期末 | 以试点学生的平台表现回归校准字典档位；复核冻结参数（见第 3 节） | 字典 v2 + 校准报告 + 全量重算 | 重算前后差异可逐条审计；企业侧试读画像反馈收集完成 |

## 4. 风险与对策

| 风险 | 对策 |
|------|------|
| 冷启动：学生无画像、企业无岗位 | 简历 / JD 双向导入通道（《04》4.7）把存量文档低摩擦翻译进来；首批实训项目由战略合作企业保底供给 |
| 评价数据质量：导师敷衍或拒填 | 交互红线（10 秒 / 1 分钟）+ 未观察默认 N/A、不要求全填，从源头控成本（单任务条目上限 20，仅防滥标）；首轮校准复核观察密度（《06》第 3 节） |
| 企业供给质量：命题作业化 | 预熟化价值的内生杠杆（《00》5.3）——项目越真实，预熟化收益越大，企业自驱供给质量 |
| 等级通胀 | 不做防作弊机制（定案），由同侪分布相对刻度吸收 + 平台原生证据作校准锚 |
| 试点期结论误用 | 阶段 4 明确"内部使用，不对外输出结论"，以全局**"结论对外"开关**执行。作用域（关闭时）：企业端候选 / 人才搜索 / 报名筛选视图一律降为经历与参与记录，不见等级、覆盖率、角色等级与同侪分布；简历导出与分享链接不输出等级（经历事实与证书仍可验，《04》第 4.7 节）；高校端、学生本人、审核队列与审计链内部仍可见完整结论（内部校准用）；证书验证本不含等级不受影响（《07》第 3.5 节）。开关由运营专员执行、平台框架委员会决策留痕（《07》第 3.1 节）；对外输出以字典 v2 发布后为界 |
| 直录制 24h 拒绝窗后、开始前无法除名问题学生 | 接受该限制（定案，不增设"取消录取"）：开项后走清退通道（《08》第 7 节）；报名测评与附言辅助前置筛查 |
| 报名截止后席位释放无人可补（支付超时 / 被拒 / 开始前退出），临界项目可能因此流标 | 接受该限制（定案，不设补录通道、不重开报名，《08》第 4.5 节）：录取链条缓冲压缩窗口期；企业将名额设在人数下限之上自担余量 |
| 中止 / 撤项审核悬挂期间项目继续运行 | 悬挂期间过程域不冻结（避免未获批就停摆），获批瞬间收口（《08》第 2 节）；运营积压靠队列逾期标注与人工调度 |
